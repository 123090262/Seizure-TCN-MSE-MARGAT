# 当前数据划分内存缓存设计

## 背景与目标

服务器 profiling 显示，2 秒窗口训练的单 batch 平均耗时为 1.2385 秒，其中 DataLoader 等待 1.1854 秒，前向与反向合计仅 0.0524 秒。连续 EEG 缓存位于 `ROTA=1` 的虚拟旋转磁盘，现有 DataLoader 会从 683 个 mmap 记录文件随机切片，导致 GPU 长时间等待数据。

本次修改的目标是消除每个 epoch 的随机磁盘读取，同时保持数据划分、标签、归一化、模型和评价协议不变。最终 mixed 10-fold 仍由 10 个独立调度任务训练，每个任务只缓存自己的 train、val 和 test 窗口。

## 范围

修改范围限定为：

- 在训练配置中增加内存缓存开关；
- 在 `src/data.py` 中增加当前 split 的内存物化路径；
- 增加等价性与回归测试；
- 更新 README 中的内存要求、运行方式和十折提交方式。

本次不改变模型结构、损失函数、优化器、随机种子、类别平衡、早停、阈值选择和 checkpoint 格式，也不增加单任务串行训练十折的入口。

## 数据流

`create_dataloaders` 仍先调用现有 `make_split`，得到完全相同的 train、val 和 test 索引。内存缓存关闭时继续使用原有 mmap Dataset。

内存缓存开启时，每个 split 按以下步骤构建：

1. 根据窗口目录取得 `record_id`、起点和标签；
2. 仅为本 split 分配连续 `float32` 窗口数组；
3. 按 `record_id` 和起点排序读取，以提高旋转磁盘访问局部性；
4. 使用现有患者级 mean/std 执行同样的逐通道 Z-score；
5. 将结果写回该样本在原 split 中的位置，保持样本与标签顺序不变；
6. 后续 epoch 只从内存数组取样，不再访问记录文件。

2 秒第 0 折的 train、val 和 test 合计约需 1.13 GiB。服务器容器内存上限为 32 GiB，满足该方案；61 GiB 的完整连续记录不会载入内存。

## 配置与兼容性

在 `train` 配置中增加 `cache_in_memory: true`。实现通过安全默认值兼容没有该字段的旧配置：缺省时使用原 mmap 路径。

内存模式将使用 `num_workers: 0`，避免多进程复制大数组。mmap 回退模式继续使用配置中的 `num_workers`。缓存模式属于可复现运行配置，会随现有 `config.yaml` 和 checkpoint 一同保存。

## 日志与错误处理

物化前记录 split 名称、窗口数和估计内存；完成后记录耗时。数组分配失败时保留原始 `MemoryError`，并补充清楚的 split、所需字节数和关闭内存缓存的方法，不静默退回 mmap，以免实验在未知性能模式下运行。

## 测试与验证

自动化测试至少覆盖：

- 内存 Dataset 与 mmap Dataset 对同一索引返回完全相同的 `float32` 张量和标签；
- 按记录排序读取后，输出仍保持原 split 顺序；
- `cache_in_memory: false` 保持原有行为；
- 内存模式的 DataLoader 能完成一个 batch；
- 原有数据划分、模型、训练和评价测试继续通过。

本地验证执行语法检查、完整 pytest 和最小 CPU 前向/反向测试。服务器上传后先用真实第 0 折重复 30-batch profiling；只有在 DataLoader 等待显著下降且数值等价检查通过后，才分别提交 mixed 10-fold 的折 0–9。

## 科研边界

该修改只改变数据的物理读取位置和读取顺序，不改变逻辑样本顺序或实验成员。患者级归一化仍是既定的 transductive 协议；mixed 10-fold 仍是患者混合的窗口级评价，不能解释为未见患者泛化。
